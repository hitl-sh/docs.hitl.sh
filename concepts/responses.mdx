# Responses

When a workflow execution reaches a human review node, it creates a **response request** -- a structured prompt sent to one or more reviewers. The reviewer's answer is the **response**. Responses are the primary output of human review in HITL.sh.

## How Responses Work

<Steps>
<Step title="Execution hits a human review node">
The workflow pauses and creates a response request based on the node's configuration (response type, reviewer assignment, timeout).
</Step>

<Step title="Reviewers are notified">
Assigned reviewers receive push notifications on the mobile app and see the item in their web dashboard inbox.
</Step>

<Step title="Reviewer submits a response">
The reviewer reads the content, makes a decision, and submits their structured response (e.g., selecting an option, entering text, or providing a rating).
</Step>

<Step title="Execution continues">
The response data is added to the execution context and the workflow continues to the next node.
</Step>
</Steps>

## Response Types

HITL.sh supports seven response types. Each human review node is configured with one:

## Responses and Executions

Responses are grouped by **execution**. Each execution represents a single run of a workflow, and it may produce one or more responses if the workflow contains multiple human review nodes or uses fan-out mode.

```
Workflow Execution #42
  +-- Human Review Node "Content Check"
  |     Response: "approve" by Sarah (2m 15s)
  |
  +-- Human Review Node "Legal Review"
        Response: "approved with edits" by James (8m 30s)
```

You can view all responses for an execution in the **Executions** tab of the workflow designer.

## Fan-Out and Endorsement

Human review nodes support two multi-reviewer modes:

<CardGroup cols={2}>
<Card title="Fan-Out" icon="arrows-split-up-and-left">
Send the review to multiple reviewers in parallel. All responses are collected and available downstream. Use this when you need multiple perspectives (e.g., collecting ratings from 5 reviewers).
</Card>

<Card title="Endorsement" icon="thumbs-up">
Require a minimum number of matching responses before the execution continues. For example, require 3 out of 5 reviewers to approve before proceeding. If the threshold is not met, the node resolves with a rejection.
</Card>
</CardGroup>

## Response Status

Each response request has a status:

| Status | Description |
|--------|-------------|
| `pending` | Waiting for a reviewer to respond |
| `completed` | Reviewer submitted their response |
| `timeout` | No response received before the deadline; default response used |
| `cancelled` | The execution was cancelled before a response was submitted |

## Timeout and Default Responses

Every human review node should have a timeout and a default response configured. If no reviewer responds within the timeout period, the default response is used and the execution continues.

```
Timeout: 3600 seconds (1 hour)
Default Response: "reject"
```

This prevents executions from stalling indefinitely.

## Viewing Responses

You can view responses in several places:

- **Executions tab**: See all responses for a specific workflow execution
- **Inbox**: Reviewers see pending response requests and can submit responses
- **API**: Query execution results programmatically
