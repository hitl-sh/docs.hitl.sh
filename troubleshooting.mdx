## Starting runs

<AccordionGroup>
<Accordion title="409: Workflow is a draft (or paused)">
Only active workflows run. Open it in the editor and click **Activate** (or [`POST /workflows/:id/activate`](/api-reference/workflows/activate)). If activation refuses, its message says what to fix, for example a review step without a question.
</Accordion>
<Accordion title="401 or 403">
`401`: the key is missing or wrong. Check `Authorization: Bearer hitl_live_…` and try [`GET /test`](/api-reference/account/test-key) or `hitl whoami`. A regenerated key replaces the old one.

`403` with `confirmation_required`: the key came from agent signup and the human has not confirmed it. Ask them for the 6-digit code from the email and run `hitl signup confirm <code>`. Other `403`s: the key lacks a scope.
</Accordion>
<Accordion title="404: Workflow not found">
The id is wrong, or the workflow belongs to another account than the key's. `hitl workflows list` shows the ids your key can see.
</Accordion>
<Accordion title="The question shows empty fields">
The review step reads fields the input did not have. Compare your input with [`GET /workflows/:id/input`](/api-reference/workflows/input): paths are case-sensitive and nested (`customer.email` means `{"customer": {"email": ...}}`).
</Accordion>
</AccordionGroup>

## Reviewers

<AccordionGroup>
<Accordion title="Nobody got the question">
- Check the workflow's **Humans** tab: invited people only receive requests once they accept.
- Check the review step's **Reviewers** tab: if people or groups are picked, only they are asked.
- The request is always in the [web inbox](/answering/web-inbox) of each reviewer, even if push failed.
</Accordion>
<Accordion title="No push notification on the phone">
Allow notifications for HITL in the phone's settings, and in the app under **Account → Notifications & sounds**. Make sure the reviewer is signed in with the email they were invited with.
</Accordion>
<Accordion title="A join code doesn't work">
Codes look like `HITL-XXXXXX`. The owner may have replaced the code (**New code**) or turned it off: ask for the current one. You must be signed in to join.
</Accordion>
<Accordion title="We hit the humans limit">
Your plan limits how many humans you have. See [Billing](/billing).
</Accordion>
</AccordionGroup>

## Getting the answer

<AccordionGroup>
<Accordion title="The run stays pending_review">
Nobody has answered yet. `waiting_for.timeout_at` is the deadline; after it the step's default answer is used, or the run ends `timed_out`. Remind the reviewers, or set a shorter deadline.
</Accordion>
<Accordion title="My callback URL never receives anything">
- It must be `https` on a public host; private addresses and redirects are refused.
- Answer with a `2xx`. Other `4xx` statuses stop delivery; `5xx`, `408` and `429` are retried for 24 hours.
- `GET /executions/:id` shows the delivery under `callback`: `state`, `attempts`, `last_status`, `last_error`.
</Accordion>
<Accordion title="Signature verification fails">
Compute the HMAC over `"<t>.<raw body>"` exactly as received, before parsing JSON, with the workflow's webhook secret. See [Webhooks](/guides/webhooks#verify-the-signature).
</Accordion>
<Accordion title="429 while polling">
Use `?wait=60` so each call waits for the answer instead of returning at once, or use a callback or webhook.
</Accordion>
</AccordionGroup>

## Integrations

<AccordionGroup>
<Accordion title="The MCP server shows no tools or fails to start">
It needs `HITL_API_KEY` in its environment (or a key saved with `hitl login`). Run `npx -y @hitl-sh/cli whoami` with the same environment to check the key, then restart the client.
</Accordion>
<Accordion title="My workflow is missing from the n8n, Zapier or Make list">
Those lists show active workflows only. Activate it, then refresh the list.
</Accordion>
<Accordion title="n8n Callback mode never resumes">
Callback mode needs n8n to be reachable from the internet over `https` (`WEBHOOK_URL`). Use **Poll** otherwise.
</Accordion>
<Accordion title="Make's Watch Workflow Runs gets nothing">
The watching scenario must be on when the run finishes. Pick the same workflow in both scenarios.
</Accordion>
</AccordionGroup>
