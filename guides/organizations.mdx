# Organizations

Organizations let you group team members, scope loops, and manage settings in one place. They're designed for teams that need centralized control over their HITL.sh workflows.

## What Are Organizations?

An organization is a shared workspace where team members collaborate on review workflows. Organizations provide:

<CardGroup cols={2}>
<Card title="Centralized Management" icon="building">
Manage all team members, loops, and settings from a single dashboard
</Card>

<Card title="Org-Scoped Loops" icon="circle-nodes">
Create loops that belong to the organization rather than individual users
</Card>

<Card title="Role-Based Access" icon="shield-halved">
Assign roles (owner, admin, member, viewer) to control who can do what
</Card>

<Card title="Enterprise Settings" icon="gear">
Configure approval chains, escalation policies, and audit retention
</Card>
</CardGroup>

## Organization Plans

Organizations are available on two plan tiers:

| Feature | Business | Enterprise |
|---------|----------|------------|
| Team members | Unlimited | Unlimited |
| Org-scoped loops | Yes | Yes |
| Role-based access control | Yes | Yes |
| Approval chains | — | Yes |
| Escalation policies | — | Yes |
| Custom audit retention | 90 days | Configurable |

## Creating an Organization

<Steps>
<Step title="Open the Dashboard">
Navigate to [my.hitl.sh](https://my.hitl.sh) and sign in to your account.
</Step>

<Step title="Create Organization">
Click the organization switcher in the sidebar and select **Create Organization**. Enter a name for your organization — a URL-friendly slug will be generated automatically.
</Step>

<Step title="Choose a Plan">
Select either **Business** or **Enterprise** depending on your needs. You can upgrade later.
</Step>

<Step title="Invite Members">
Once created, invite team members by email or share the organization's invite code.
</Step>
</Steps>

## Organization Structure

### Members

Every organization has a list of members, each with an assigned role:

```json
{
  "user_id": "64a1b2c3d4e5f6a7b8c9d0e1",
  "role": "admin",
  "joined_at": "2026-07-15T10:30:00Z"
}
```

See [Roles & Permissions](/guides/roles-permissions) for details on the 4-tier role model.

### Settings

Organization settings control enterprise features:

<ParamField body="require_approval_chains" type="boolean" default="false">
When enabled, all requests in the organization must go through an approval chain before being finalized. Enterprise plan only.
</ParamField>

<ParamField body="escalation_enabled" type="boolean" default="false">
When enabled, requests can be escalated to higher-level reviewers when not resolved within a configurable timeframe. Enterprise plan only.
</ParamField>

<ParamField body="audit_retention_days" type="integer" default="90">
Number of days to retain audit logs for organization activity. Enterprise plans can configure this value.
</ParamField>

## Org-Scoped Loops

Loops created within an organization are scoped to that organization. This means:

- All organization members with appropriate roles can access the loop
- Requests in org-scoped loops respect the organization's settings (e.g., approval chains)
- Loop analytics roll up to the organization's dashboard
- The `X-Org-ID` header can be used to filter inbox items by organization

### Creating an Org-Scoped Loop

When creating a loop via the API, include the organization ID:

<CodeGroup>

```python Python
request_data = {
    "name": "Content Review Queue",
    "description": "Review AI-generated content before publishing",
    "org_id": "64a1b2c3d4e5f6a7b8c9d0e1"
}

response = requests.post(
    "https://dev.api.hitl.sh/v1/api/loops",
    headers={"Authorization": f"Bearer {api_key}"},
    json=request_data
)
```

```javascript Node.js
const requestData = {
    name: "Content Review Queue",
    description: "Review AI-generated content before publishing",
    org_id: "64a1b2c3d4e5f6a7b8c9d0e1"
};

const response = await axios.post(
    "https://dev.api.hitl.sh/v1/api/loops",
    requestData,
    { headers: { Authorization: `Bearer ${apiKey}` }}
);
```

</CodeGroup>

## Invite Codes

Organizations support invite codes that let new members join without requiring an individual email invitation.

### How Invite Codes Work

<Steps>
<Step title="Generate Code">
An owner or admin generates an invite code from the organization settings page.
</Step>

<Step title="Share Code">
Share the invite code or link (e.g., `my.hitl.sh/org-invite/{code}`) with prospective members.
</Step>

<Step title="Join Organization">
Recipients visit the invite link, sign in (or create an account), and are automatically added to the organization as a **member**.
</Step>
</Steps>

### Deep Link Support

Invite links work across platforms:
- **Web:** Opens the join page directly at `my.hitl.sh/org-invite/{code}`
- **Mobile:** Deep links carry the invite code through the sign-in flow, so new users are added to the organization after completing registration

## Organization Switcher

If you belong to multiple organizations, the sidebar in the web dashboard includes an organization switcher. Switching organizations updates:

- The loops visible in the sidebar
- The inbox filter to show only that organization's requests
- The settings page to show that organization's configuration
- Analytics and usage data scoped to the selected organization

## Best Practices

<AccordionGroup>
<Accordion title="Start with Clear Roles">
Assign roles intentionally from day one. Use **viewer** for stakeholders who need visibility, **member** for active reviewers, **admin** for team leads, and reserve **owner** for the account holder.
</Accordion>

<Accordion title="Use Org-Scoped Loops">
Create loops within the organization rather than under individual accounts. This ensures continuity if team members leave and keeps analytics centralized.
</Accordion>

<Accordion title="Configure Audit Retention Early">
If your organization has compliance requirements, set the audit retention period during setup. Audit logs cannot be recovered after they expire.
</Accordion>

<Accordion title="Use Invite Codes for Onboarding">
For teams with frequent turnover, use invite codes instead of individual email invitations. This simplifies onboarding and reduces admin overhead.
</Accordion>
</AccordionGroup>
