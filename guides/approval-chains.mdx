# Endorsement Reviews

Endorsement is a review mode available on human review nodes in the workflow designer. It requires a minimum number of reviewers to reach the same decision before the workflow execution continues. Use endorsement when a single reviewer's opinion is not sufficient -- for example, requiring 3 out of 5 reviewers to approve content before it is published.

## How Endorsement Works

<Steps>
<Step title="Configure the human review node">
In the workflow designer, select a human review node and set the review mode to **Endorsement**.
</Step>

<Step title="Set the threshold">
Specify the minimum number of matching responses required. For example, "3 of 5 must approve."
</Step>

<Step title="Assign reviewers">
Select a group from your Humans directory. All members of that group receive the review request.
</Step>

<Step title="Reviewers respond">
Each reviewer submits their decision independently. They do not see other reviewers' responses.
</Step>

<Step title="Threshold reached">
Once the required number of matching responses is received, the node resolves and the workflow continues. If the threshold cannot be reached (e.g., too many rejections), the node resolves with a rejection.
</Step>
</Steps>

## Endorsement vs. Fan-Out

Human review nodes support two multi-reviewer modes:

| Feature | Fan-Out | Endorsement |
|---------|---------|-------------|
| **Purpose** | Collect all responses | Reach consensus |
| **Resolution** | Waits for all reviewers | Resolves when threshold is met |
| **Output** | Array of all responses | The consensus decision |
| **Best for** | Collecting ratings, gathering feedback | Approval gates, compliance sign-off |

## Configuration

### Review Mode Settings

<ParamField body="mode" type="string" required>
Set to `"endorsement"` to enable endorsement mode.
</ParamField>

<ParamField body="threshold" type="integer" required>
The minimum number of matching responses required for the node to resolve as approved. Must be less than or equal to the number of assigned reviewers.
</ParamField>

<ParamField body="reviewers" type="string" required>
A group from your Humans directory, or a list of individual people.
</ParamField>

<ParamField body="timeout_seconds" type="integer">
How long to wait for responses before using the default response (60-86400 seconds).
</ParamField>

<ParamField body="default_response" type="varies">
The fallback value used if the timeout is reached before the threshold is met.
</ParamField>

### Example Configuration

A content publishing workflow that requires 3 out of 5 editors to approve:

```
Node: Human Review - "Editorial Approval"
  Response Type: Single Select
  Options: Approve, Reject
  Review Mode: Endorsement
  Threshold: 3
  Reviewers: "Editorial Team" (5 members)
  Timeout: 86400 seconds (24 hours)
  Default Response: Reject
```

## Use Cases

### Content Publishing Gate

Require multiple editors to approve an article before it is published:

- **Reviewers**: Editorial Team (5 people)
- **Threshold**: 3 approvals
- **Response type**: Single Select (Approve / Reject)
- **Timeout**: 24 hours with "Reject" as default

### Compliance Sign-Off

Require sign-off from multiple compliance officers:

- **Reviewers**: Compliance Team (3 people)
- **Threshold**: 2 approvals
- **Response type**: Single Select (Approve / Reject / Escalate)
- **Timeout**: 4 hours with "Escalate" as default

### Multi-Department Approval

For cross-functional approvals, use multiple human review nodes in sequence instead of endorsement. Each node is assigned to a different group:

```
Trigger
  +-- Human Review: "Legal Review" (Legal Team, first response wins)
  +-- Human Review: "Finance Review" (Finance Team, first response wins)
  +-- Human Review: "Engineering Review" (Engineering Team, first response wins)
  +-- Action: Proceed with approved item
```

This is the workflow equivalent of a sequential approval chain.

## Best Practices

<AccordionGroup>
<Accordion title="Set realistic thresholds">
Do not require all reviewers to respond. A threshold of 3 out of 5 is more practical than 5 out of 5, since one unavailable reviewer would block the entire workflow.
</Accordion>

<Accordion title="Use appropriate timeouts">
Set timeouts based on the urgency of the review. Short timeouts (1-4 hours) for time-sensitive content, longer timeouts (24-48 hours) for compliance reviews.
</Accordion>

<Accordion title="Choose safe defaults">
The default response should be the most conservative option. For approval gates, use "Reject" as the default so that content is not published if reviewers do not respond in time.
</Accordion>

<Accordion title="Keep reviewer groups sized appropriately">
Endorsement works best with 3-7 reviewers. Too few and a single absence blocks the workflow. Too many and you are waiting for responses that may never come.
</Accordion>
</AccordionGroup>

## Migrating from Approval Chains

If you previously used the approval chains feature, endorsement reviews are the replacement:

- **Sequential approval chains** become multiple human review nodes connected in sequence in your workflow
- **Parallel approval chains** become a single human review node in endorsement mode
- **`require_all` steps** become endorsement with a threshold equal to the number of reviewers

See the [Migration Guide](/guides/migration) for more details.
